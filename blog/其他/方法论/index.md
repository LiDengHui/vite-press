# 方法论导航

[[toc]]

这个目录收集的是可以反复使用的思维工具与方法论。它们来自不同的领域——时间管理、产品创新、质量管理、行为科学、组织协作——但共同点是：都试图把一件说不清的难事，拆成一套说得清、做得出的步骤。读它们的目的不是记住名词，而是在遇到合适的问题时，能想起有一套现成的思路可以借用。

## 建议的阅读顺序

如果只是随便翻翻，可以按兴趣挑。如果想建立一套相互配合的体系，建议按下面的顺序读。

1. 先读 GTD 搞定方法和番茄工作法。前者解决“有哪些事、该做哪件”，后者解决“坐下来怎么专注地做”，两者合起来就是最基础的执行系统，几乎所有其他方法都要落在它们之上。

2. 接着读深度工作。它解释了为什么专注本身值得投资，让你在使用番茄钟时明白自己在保护什么。

3. 然后读福格行为模型和 WOOP 心理对照法。这两篇处理的是更底层的问题——行为为什么会发生、目标为什么会落空。它们能解释你在执行前两个方法时为什么会卡住，并提供具体对策。

4. 如果你是做产品或带团队的，再读精益创业、设计思维和敏捷开发与 Scrum。这三篇彼此衔接：设计思维负责发现真问题，精益创业负责用最小成本验证方向，敏捷与 Scrum 负责把验证过的方向持续交付出来。

5. 最后读六西格玛。它适合流程已经稳定、需要在质量上精益求精的场合，是一套偏工程和数据的方法，可以在前几篇打下的基础上单独深入。

## 按需求挑选

如果你带着一个具体问题来，可以直接从这里找到对应的那一篇。

| 你现在的困扰 | 建议先读 |
| --- | --- |
| 事情太多，总怕漏掉重要的 | GTD 搞定方法 |

| 一坐下就想刷手机、静不下来 | 深度工作 |
| 想做一件事却总坚持不了几天 | 福格行为模型 |
| 计划写了很多，最后全落空 | WOOP 心理对照法 |
| 做出来的东西用户不用 | 设计思维 |

| 需求天天变，交付总延期 | 敏捷开发与 Scrum |
| 流程老出问题，改了还会犯 | 六西格玛 |

## 怎么用好这些方法论

- 一次只用一个。同时套用多种方法，往往哪个都学不精，先选一个跑通再说。
- 先小范围试验。不必全盘照搬，可以只借用其中一个步骤或规则，看是否真的有效。
- 关注原理而不是术语。术语会变，但“为什么有效”的逻辑可以迁移到别的场景。
- 定期回顾。任何方法都需要根据实际效果调整，而不是设定完就放在一边。
- 承认边界。每种方法论都有它不适用的场合，用错场景比不用更糟。

不必一次读完，也不必全盘照搬。找到与自己当下问题最匹配的那一个，先做起来，比读完十本理论更有用。
