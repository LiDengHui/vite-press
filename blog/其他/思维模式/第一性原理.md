# 第一性原理

[[toc]]

第一性原理（First Principles）是一种把问题拆解到最基本、最确定的事实，再从这些事实出发重新推导答案的思考方式。

它要解决的问题是：当我们习惯于「别人都这么做」「一直都是这样」时，往往会接受大量未经检验的假设，从而错过真正更优的解法。它最早是哲学概念，用来追问世界的本原；后来被工程师和创业者借来重新设计成本结构和技术路线，埃隆·马斯克是当代最常引用它的实践者。它既不是天才的专利，也不是玄学，而是一套可以被训练、被拆成步骤的思考纪律。

## 一句话概括

> 不要用类比推理，要回到最底层的事实，从那里重新往上推。

## 核心思想

这个概念最早来自亚里士多德。他在讨论事物何以成立时，提出存在一些「第一原理」，即不能被进一步推导、也无法被推翻的最基本命题，其他知识都建立在它们之上。两千多年后，这套思路被重新用于工程和商业决策：如果一个结论依赖一连串假设，那么只要其中某个假设站不住脚，结论就可能整体崩塌。

与之相对的是「类比推理」，也就是参照已有的做法稍作修改。类比推理省事、风险低，在稳定环境里效率很高，但它的天花板就是现有方案的天花板。你照着别人的样子做，最好的结果也就是和对方差不多。第一性原理的价值，恰恰在于它允许你越过现有方案，直接问「物理上、经济上、逻辑上真正允许的极限在哪里」。

马斯克常举的例子是电池。早年行业普遍认为电池组每千瓦时成本要六百美元左右，因为过去一直如此。他没有接受这个数字，而是把电池拆成原材料——碳、镍、铝、钢等——在伦敦金属交易所查它们的现货价格，发现原材料成本只占其中的一小部分。

这个差额不是物理定律，而是工艺、供应链和行业惯例造成的。既然差额来自工艺，那就可以被改进。特斯拉后来的成本下降，正是从这种拆解开始的。类似的思路也出现在 SpaceX 的火箭成本上：他同样把火箭拆成材料成本，发现原材料只占售价的一小部分，从而判断制造成本有大幅压缩的空间。

所以第一性原理的本质不是「聪明」，而是一种纪律：坚持区分「事实」与「因为大家都这么认为」。它迫使你把论证的每一层都摊开检查，只在确实无法再拆的地方停下来。它反对的也不是经验本身，而是不加检验地接受经验中的默认前提。

它还有一个常被忽略的好处：能抵抗「权威光环」。当一个领域里所有人都重复同一个说法时，这个说法会获得一种虚假的确定性。第一性原理要求你回到原始数据和基本约束，哪怕结论和权威相悖。真正可靠的判断，往往来自自己亲手验证过的那部分事实。

它和「怀疑一切」也有区别。怀疑一切会让人瘫痪，第一性原理则要求你在怀疑之后必须重建。拆开是手段，重新搭起一个能落地的方案才是目的。只拆不建，就变成了虚无主义，而不是思考工具。

最后要提醒的是，第一性原理并非总是更快或更好。从零推导成本高、耗时长，只适合那些值得重新设计的重大问题。对绝大多数日常决策，经验和类比是更划算的选择。把有限的精力用在真正重要的少数问题上，才是这套方法的正确用法。

## 怎么用

1. **写下你的结论或目标。** 先明确你到底想解决什么问题，比如「这个项目必须花三个月」或「这个东西只能卖这个价」。目标越具体，后面的拆解越有方向。
2. **列出支撑它的所有假设。** 把「为什么必须这样」逐条写下来，包括时间、成本、人力、技术、法规等各方面，宁可多写，不要漏掉。
3. **逐个追问「这是事实还是惯例」。** 对每条假设问：它是物理定律、硬性约束，还是只是过去有人这么做过？这一步的产出，是一张分类清单。
4. **把惯例性假设暂时划掉。** 只保留真正不可动摇的约束，看看在剩下的空间里答案会变成什么样。
5. **从底层事实重新推导。** 用保留的事实作为起点，重新构建一个方案，哪怕它一开始看起来很荒谬。荒谬感往往正是旧假设被打破的信号。
6. **回到现实做可行性校验。** 检查新方案的成本、风险和落地条件，把它变成可执行的步骤，而不是停留在纸面。
7. **小步验证关键假设。** 用最小可行实验去测试最不确定的那一环，而不是一次性押上全部资源。
8. **区分「不能做」和「不容易做」。** 前者是约束，后者只是难度，不要把难度误当成约束。
9. **记录并复用。** 把这次拆出来的底层事实和约束保存下来，它们通常能复用到下一个类似问题上。
10. **设定重估周期。** 技术、市场和法规会变，过去的事实可能失效，隔一段时间要重新验证。

## 示例

以「为什么这个功能要三个月才能上线」为例：

| 假设 | 类型 | 追问后的结论 |
| --- | --- | --- |
| 需求必须全部完成才能上线 | 惯例 | 可以先上线核心路径，其余迭代 |
| 必须等所有设计稿定稿 | 惯例 | 关键页面定稿即可并行开发 |
| 数据库结构不能改 | 半事实 | 迁移有成本，但不是不可能 |
| 必须通过全套回归测试 | 事实 | 这是硬约束，不能省 |
| 一个人只能做一部分 | 惯例 | 可拆分接口并行推进 |
| 必须用现有的老框架 | 惯例 | 若评估后收益大，可以替换 |
| 必须等第三方接口就绪 | 半事实 | 可先用桩数据开发，后期对接 |
| 上线必须零缺陷 | 惯例 | 允许灰度和小范围试错 |
| 必须由一个人全程负责 | 惯例 | 可轮换或结对，降低单点依赖 |

拆解之后会发现，真正不可动摇的只有「回归测试」这类硬约束，而大部分「必须」其实是可以重新谈判的惯例。时间不是被物理定律锁死的，而是被一堆默认前提锁死的。当你把这张表摆到台面上，讨论就从「能不能快」变成了「哪条假设可以改」，决策质量会明显提升。

再看电池成本这个案例，把行业惯例拆开之后是这样：

| 成本项 | 行业默认 | 拆解后的事实 |
| --- | --- | --- |
| 原材料 | 笼统计入总成本 | 只占总成本的一小部分 |
| 工艺与制造 | 视为固定 | 可通过规模化和改进降低 |
| 供应链加价 | 视为必要 | 可通过垂直整合压缩 |
| 行业利润惯例 | 视为定价基础 | 属于惯例，不是物理约束 |

另一个经典案例是运输成本。有人以为「运货必须用卡车」，但从底层看，真正需要的是「把货物从 A 运到 B」。一旦这样定义，铁路、水运、无人机乃至分布式仓储都成了可选方案。改变对问题的定义，往往比在旧方案里拼命优化更有效。

## 适用场景

- 面对一个「行业惯例就是如此」的成本或价格结构，怀疑其中有水分时。
- 要重新设计一条技术路线、产品形态或商业模式时。
- 团队陷入「我们一直都这么做」的惯性，需要打破僵局时。
- 学习一个新领域，想搞清哪些是基本原理、哪些只是流行的做法时。
- 需要给一个反直觉的方案做论证，必须从根上说服他人时。
- 评估一项长期投入是否值得，需要看它的理论上限时。
- 被复杂问题困住，需要找到那个真正不能让步的核心约束时。
- 谈判中，需要识别对方哪些条件是硬性的、哪些只是开价时。

## 常见误区

- **把所有事都当第一性原理来推。** 绝大多数日常决策用类比和经验就够了，事事从头推演会耗尽精力。
- **把「我觉得」当成底层事实。** 第一性原理要求的是可验证的事实，而不是个人偏好或直觉。
- **忽视隐藏约束。** 有些假设看似惯例，其实背后有法规、安全或物理原因，拆之前要确认清楚。
- **只拆不建。** 拆解只是第一步，真正的价值在于从底层重新构建出可行的方案。
- **误以为它总是更快。** 从零推导通常比借鉴更慢、更贵，只在收益足够大时才值得。
- **用它来否定一切专家意见。** 尊重事实不等于否定经验，专家经验往往正是对大量事实的压缩。
- **忽略人的因素。** 组织、文化、信任这些难以量化的东西，同样是真实约束。
- **一次拆太多问题。** 同时重推多个大问题，会导致每个都做不透。
- **把难度当约束。** 「很难」和「不可能」是两回事，混为一谈会过早放弃可行方案。

## 相关工具

- 系统思维：第一性原理帮你找到最底层的部件，系统思维帮你理解这些部件如何相互作用。
- 逆向思维：拆解到最底层之后，反过来问「什么一定会让它失败」，能补上正向推导的盲区。
- 二阶思维：从底层推出方案后，再想一层长期后果，避免只优化眼前指标。
- 奥卡姆剃刀：在多个从底层推出的解释中，优先选择假设更少的那个。
- 能力圈：只有在你真正理解的领域，拆解才靠得住，否则容易把无知当底层事实。
- 概率思维：底层事实往往也是概率性的，用分布而非单点来刻画更准确。
