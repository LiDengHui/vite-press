# 六顶思考帽

[[toc]]

六顶思考帽由爱德华·德博诺在 1985 年出版的同名著作中提出。它把思考分成六个角度，每种角度用一顶帽子表示，同一时间所有人戴同一顶帽子。

它解决的是会议中"有人只顾挑毛病、有人只顾唱赞歌、讨论变成辩论"的问题，让团队把注意力从互相反驳转向平行探索。它适合需要兼顾创意与风险、又要快速形成结论的团队讨论。

## 一句话概括

> 让所有人同时用同一种方式思考，把"对人"的争论变成"对角度"的切换。

## 核心思想

第一层逻辑是平行思考。传统讨论里，赞成和反对同时发声，双方为了维护立场互相攻击，信息反而被掩盖。六顶思考帽要求同一时刻所有人朝同一个方向看：一起列事实，一起想风险，一起找创意。观点不再属于某个人，而是属于当前那顶帽子，讨论的对抗性大幅下降。

第二层逻辑是六种帽子各代表一种思考模式。白帽关注事实与数据，只谈已知信息和缺口；红帽表达直觉和情绪，允许不加论证地说出感受；黑帽做批判和风险评估，指出问题和隐患；黄帽看价值和机会，寻找可行性和好处；绿帽负责创意，提出新想法和替代方案；蓝帽管理流程，负责定义议题、安排顺序、总结结论。

第三层逻辑是"戴帽子"是一种可以主动调用的能力。多数人习惯固定在自己的思维模式里，有人天生爱挑刺，有人总说好话。六顶帽子让人有意识地切换：需要发散时戴绿帽，需要收敛时戴黑帽。这种切换能力比固定的性格倾向更有价值。

第四层逻辑是顺序可以设计。常见顺序是：蓝帽开场定议题，白帽摆事实，绿帽出方案，黄帽评价值，黑帽评风险，红帽表达感受，蓝帽收尾做决定。顺序不是死的，简单议题可以省略某些帽子，但蓝帽的开场和收尾通常都要保留。

第五层逻辑是分离"想法"和"想法的人"。当黑帽指出风险时，它不是针对提出方案的人，而是当前阶段全体共同承担的视角。这种分离让平时不敢说话的人也能表达担忧，也让爱挑刺的人学会先看价值。团队讨论因此更完整，也更安全。

六顶思考帽的价值在于提高讨论效率，而不在于保证结论正确。它让团队更快看清一件事的全貌，但最终决策仍然需要有人负责。它是思考的组织方式，不是决策的替代品。

它也有适用范围。对于需要快速拍板的简单事务，走完整流程反而拖沓；对于情绪对立的敏感议题，结构化的帽子能有效降温。判断要不要用、用哪几顶，本身就是蓝帽的工作。

六帽的另一个价值是让沉默的人发声。传统会议里，职级高或性格强势的人往往主导讨论，其他人的想法被压制。六帽把"发言"变成"按帽子发言"，每个人在每一轮都有明确的表达角度，参与度会明显提高。

使用时不必拘泥于正式形式。日常沟通里也可以用一句话切换视角，比如"我先戴白帽说几个事实""现在换黑帽，看看风险在哪"。这种轻量化的用法，比开一场正式会议更容易坚持。

## 怎么用

1. 蓝帽开场。明确这次要讨论的议题、目标，以及接下来戴帽子的顺序和时间分配。
2. 白帽阶段。只陈述事实、数据和信息缺口，不允许评价和猜测。
3. 绿帽阶段。尽量多提方案和可能性，先追求数量，此时不评判。
   - 鼓励"疯狂"的想法，它们常能引出可行的方案。
   - 允许在别人的想法上继续发散。
4. 黄帽阶段。逐条分析方案的价值、可行性和收益。
5. 黑帽阶段。逐条分析风险、成本和可能失败的原因。
   - 批判针对方案，不针对提出方案的人。
   - 说清"在什么条件下会出问题"。
6. 红帽阶段。每人用一句话表达直觉感受，允许没有理由。
7. 蓝帽收尾。总结共识、分歧和待办，明确下一步由谁在什么时候做决定。
8. 事后回顾顺序是否合适，下次针对类似议题做调整。

9. 控制每顶帽子的时间，避免某一顶占用过多时间。
   - 白帽和绿帽通常需要更长时间，黑帽容易拖长，要有意识地收尾。
10. 蓝帽要中立，负责引导而不是表达自己的立场。
11. 结论要落到具体的负责人和时间点，否则会议成果会流失。
12. 复杂议题可以分成几轮六帽讨论，每轮聚焦一个子问题。

## 示例

团队讨论"是否上线一个新功能"：

| 帽子 | 讨论内容示例 |
| --- | --- |
| 蓝帽 | 议题：是否在本季度上线智能推荐功能；顺序：白、绿、黄、黑、红、蓝 |
| 白帽 | 目前有 3 名后端可用，推荐算法有现成方案，历史数据显示相关功能使用率约 12% |
| 绿帽 | 可以全量上线，也可以先做 10% 灰度；可以用规则推荐替代模型推荐先验证 |
| 黄帽 | 若使用率提升到 25%，预计带动日活增长；灰度方案风险可控且能快速拿到数据 |
| 黑帽 | 模型训练数据不足，可能推荐不准；本季度人力已满，挤占其他功能会影响交付 |
| 红帽 | 多数人对功能方向感觉兴奋，但对排期感到紧张 |
| 蓝帽 | 结论：本季度先做规则推荐的灰度版本，下季度根据数据决定是否投入模型方案 |

如果没有六帽结构，这场讨论很可能变成"支持派"和"反对派"互相说服，最后凭嗓门或职级决定。有了结构，事实、创意、价值和风险都被完整地看了一遍。

六帽也适合个人使用。做重大决定时，可以先列出所有事实，再逼自己想出三个方案，然后分别写下好处和风险，最后诚实面对自己的直觉感受。一个人也可以有意识地切换帽子，避免被单一视角困住。

## 适用场景

- 团队决策会议，尤其是容易陷入争论的议题。
- 需要同时评估价值与风险的方案评审。
- 头脑风暴，用绿帽保证创意阶段不被过早否定。
- 复盘和事后分析，用白帽和黑帽区分事实与推断。
- 跨部门沟通，用统一的结构降低立场对立。
- 个人重大决策，用六帽自问自答，检查思考是否片面。

## 常见误区

- 把黑帽当成人身攻击或立场表达，批判变成否定人。
- 顺序僵化，任何议题都走完整流程，简单问题被拖得很长。
- 有人始终只戴一顶帽子，比如全程挑刺或全程唱好，结构失去意义。
- 绿帽阶段就开始批判，创意还没成型就被否掉。
- 红帽阶段要求给出理由，情绪表达变成又一轮辩论。
- 把六帽当投票工具，以为走完流程结论就自动正确。
- 主持人（蓝帽）不控场，讨论跑题，帽子名存实亡。
- 只开会不落地，结论没有负责人和时间点，会议成果流失。
- 把帽子当成角色扮演，为了"像"而说话，失去真实思考。
- 白帽阶段混入推断，把猜测当成事实。
- 黄帽流于空泛乐观，不给依据。
- 会议结束不明确决策人，走完流程仍无人拍板。

## 相关工具

- PDCA 循环：六帽适合讨论和决策，PDCA 适合决策之后的执行与检查。
- GROW 模型：在探索方案阶段，六帽的绿帽和黄帽可以补充 GROW 的 Options 环节。
- 艾森豪威尔矩阵：六帽理清一件事该不该做，矩阵决定它在时间上排在哪里。
- 平衡计分卡：评估方案时，可以从四个维度补充六帽的视角。
- 二八法则：在众多方案中收敛时，用来找出最关键的那少数几个。
- SMART 原则：把会议结论转成有期限、可衡量的行动项。
