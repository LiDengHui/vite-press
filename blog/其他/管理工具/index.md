# 管理工具导航

[[toc]]

## 目录说明

本目录整理了十种常用的管理工具与思维模型，覆盖目标设定、绩效衡量、持续改进、时间管理和团队决策几个方向。它们大多不是互相替代的关系，而是解决不同环节的问题：有的负责把方向写清楚，有的负责衡量做得怎么样，有的负责让讨论更有效率。

这些工具的共同点是"把模糊变清楚"。它们不提供答案，只提供结构，帮助你判断一件事该不该做、做到什么程度、怎么知道做成了。使用时不必贪多，先把一两个真正用得上的用透，比全部了解一遍更有价值。

本目录的文章都按同一套结构组织：先说清楚它是什么、解决什么问题，再讲背后的逻辑、具体步骤、真实示例，最后列出适用场景、常见误区、相关工具和参考资料。可以把它当作一份可以随手查阅的工具手册。

## 这些工具解决什么问题

按用途划分，十种工具大致落在五个环节里：

- 定目标：SMART 原则、OKR、MBO 目标管理，解决"要做什么、做到什么程度"的问题。
- 量结果：KPI、平衡计分卡，解决"怎么衡量、怎么知道做得好不好"的问题。
- 促改进：PDCA 循环，解决"做完之后怎么变更好"的问题。
- 排优先级：艾森豪威尔矩阵、二八法则，解决"时间和资源该投向哪里"的问题。
- 做决策与辅导：六顶思考帽、GROW 模型，解决"怎么让讨论更有效、让人自己想清楚"的问题。

## 工具之间的关系

几个容易混淆的概念，可以这样区分：

OKR 与 KPI：OKR 负责"进攻"，指向需要突破的方向；KPI 负责"防守"，监控业务健康度。一个季度可以没有新的 OKR，但 KPI 要一直盯着。把监控型指标塞进 OKR，会让 OKR 失去聚焦的作用。

OKR 与 MBO：OKR 继承了德鲁克目标管理的核心思想，但更强调公开透明，并刻意与考核脱钩。理解这一点，就不会把 OKR 用成一张换了名字的绩效考核表。

KPI 与平衡计分卡：平衡计分卡提供选取指标的框架，避免只看财务；KPI 提供具体的指标定义和考核方式。计分卡更像战略沟通工具，KPI 更像执行监控工具。

SMART 与其他工具：SMART 不解决"做什么"，只解决"怎么写清楚"。它可以用来打磨 OKR 的关键结果、KPI 的指标、MBO 的目标，是其他工具的通用底座。

艾森豪威尔矩阵与二八法则：两者都关于取舍。矩阵按重要与紧急分类任务，二八法则按贡献大小识别关键少数，可以配合使用。

GROW 与六顶思考帽：都用于对话和讨论。GROW 适合一对一的辅导，六顶思考帽适合多人会议，前者帮人自己想清楚，后者帮团队看全问题。

## 场景对照表

不知道从哪件工具入手时，可以先找到自己的场景：

| 你的处境 | 建议先看的工具 |
| --- | --- |
| 目标总是写不具体，年底无法验收 | SMART 原则 |
| 团队很忙，但说不清在推进什么 | OKR目标与关键结果 |
| 需要一套长期跟踪的考核指标 | KPI关键绩效指标 |
| 只盯财务数字，担心短期行为 | 平衡计分卡 |
| 想让员工更主动地承担目标 | MBO目标管理 |
| 每天被杂事填满，重要的事没做 | 艾森豪威尔矩阵 |
| 资源有限，需要判断该投向哪里 | 二八法则 |
| 改进总是一次性，成果留不下来 | PDCA循环 |
| 开会容易变成争论，结论难产 | 六顶思考帽 |
| 想辅导下属，又不想直接给答案 | GROW模型 |

## 建议阅读顺序

如果刚开始接触，建议按下面的路径阅读：

1. 先读 SMART原则，它是其他所有目标类工具的基础，学会把目标写清楚。
2. 接着读 OKR目标与关键结果 和 KPI关键绩效指标，理解"目标牵引"和"指标监控"的分工。
3. 再读 MBO目标管理 和 平衡计分卡，补上目标分解和多维度衡量的框架背景。
4. 然后读 PDCA循环，掌握执行过程中的检查与改进节奏。
5. 时间紧张、任务繁重时，读 艾森豪威尔矩阵 和 二八法则，学会做取舍。
6. 需要带团队讨论和辅导下属时，读 六顶思考帽 和 GROW模型。

## 按角色推荐

不同角色关注的重点不同，下面是一份简化的搭配建议：

| 角色 | 建议的工具组合 |
| --- | --- |
| 高管 | 平衡计分卡 + OKR + KPI |
| 团队负责人 | OKR + KPI + GROW 模型 |
| 一线管理者 | MBO 目标管理 + 艾森豪威尔矩阵 + GROW 模型 |
| 产品与运营 | KPI + 二八法则 + PDCA 循环 |
| 项目经理 | SMART 原则 + PDCA 循环 + 六顶思考帽 |
| 个人 | SMART 原则 + 艾森豪威尔矩阵 + 二八法则 |

组合的逻辑是：先用目标类工具定方向，再用衡量类工具盯结果，最后用改进类工具持续优化。角色越小，越侧重执行层面的工具；角色越大，越侧重战略层面的工具。

## 使用建议

- 工具是结构，不是答案。先想清楚自己的问题，再选工具，而不是反过来。
- 一次只引入一两个工具，用一段时间形成习惯后再增加。
- 不要追求指标或步骤的完整，真正被执行的部分才有价值。
- 定期回顾使用效果，无效就调整，不要让工具本身变成新的负担。
