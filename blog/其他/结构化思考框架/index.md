# 结构化思考框架导航

[[toc]]

这个目录收集的是结构化思考领域最常用的一组框架，共 8 篇。它们解决的是同一类问题：面对复杂、模糊、信息过载的局面时，如何把想法组织成不重不漏、可以被验证、可以被别人理解的结构。这些框架彼此不是并列的独立工具，而是一套互相咬合的体系——有的负责分类，有的负责表达，有的负责拆解，有的负责找原因。

| 文章 | 解决的问题 | 核心关键词 |
| --- | --- | --- |

| [金字塔原理](./金字塔原理.md) | 如何把想清楚的东西说明白 | 结论先行、以上统下、SCQA |
| [逻辑树](./逻辑树.md) | 如何把大问题拆成可验证的小问题 | 问题树、议题树、分解 |
| [5W2H分析法](./5W2H分析法.md) | 如何把一件事问清楚、描述完整 | 七个提问维度 |

## 建议阅读顺序

如果是第一次接触这套方法，建议按下面的顺序读，每一步都建立在前一步之上：

1. **先读 [归纳与演绎](./归纳与演绎.md)**。它是最底层的逻辑基础，决定了后面所有框架的可靠性边界。不理解归纳的或然性和演绎的前提依赖，用其他框架时容易把猜测当结论。
2. **再读 [MECE原则](./MECE原则.md)**。它是所有拆解和分类动作的共同标准，后面几乎每个框架都要求满足 MECE。
3. **接着读 [金字塔原理](./金字塔原理.md)**。它给出的是表达结构，也是整套方法的总纲——结论先行、以上统下、归类分组、逻辑递进。
4. **然后读 [逻辑树](./逻辑树.md)** 和 [假设驱动与议题树](./假设驱动与议题树.md)。这两篇讲的是怎么把问题拆开、怎么分配验证工作，是实际项目里最常用的操作手法。
5. **最后读 [5W2H分析法](./5W2H分析法.md)、[5Why分析法](./5Why分析法.md) 和 [鱼骨图](./鱼骨图.md)**。这三篇是具体场景下的战术工具：5W2H 用来把问题描述清楚，鱼骨图用来铺开候选原因，5Why 用来把选中的原因追到底。

如果已经有一定基础，也可以按问题类型直接跳读：要汇报和写作，看金字塔原理；要做分析诊断，看逻辑树与假设驱动；要排查故障和复盘，看鱼骨图与 5Why。

### 每读一篇时重点看什么

| 文章 | 阅读时重点抓住 | 最容易被跳过的地方 |
| --- | --- | --- |
| MECE原则 | 同一层只能用一个切分维度 | 用真实样本做互斥与穷尽的验证 |
| 金字塔原理 | 塔尖必须是一句有判断的结论 | SCQA 序言的四个要素顺序 |
| 逻辑树 | 叶子节点必须能对应验证动作 | 分支加总与总量是否对得上 |
| 5W2H分析法 | 七个答案之间要互相印证 | How much 与 Why 这两项 |
| 5Why分析法 | 每一步追问都要有事实依据 | 第一层原因要列全，不能只追一条 |
| 鱼骨图 | 主干类别要覆盖全面 | 画完之后必须逐条验证 |
| 假设驱动与议题树 | 假设必须可证伪 | 被推翻时要果断换假设 |
| 归纳与演绎 | 分清结论是或然还是必然 | 演绎的前提是否真实 |

## 框架之间的关系

这八个框架不是八件并列的工具，它们覆盖了从“想清楚”到“说明白”的完整链条，各自负责其中一段。

| 环节 | 主要框架 | 它负责什么 |
| --- | --- | --- |
| 判断可靠性 | 归纳与演绎 | 确认手上的证据支持到什么程度的结论 |
| 分类与拆解 | MECE原则、逻辑树 | 把整体切成不重不漏、可验证的部分 |
| 描述与提问 | 5W2H分析法 | 把一件事、一个现象问清楚、写完整 |
| 找原因 | 鱼骨图、5Why分析法 | 先铺开可能性，再纵向追到根本原因 |
| 收敛与决策 | 假设驱动与议题树 | 用最少的时间验证最关键的判断 |
| 组织与表达 | 金字塔原理 | 把结论和证据组织成别人能接受的结构 |

实际使用时，一次完整的分析往往要穿过其中好几个环节：先用 5W2H 把问题描述清楚，用 MECE 和逻辑树把问题拆开，用鱼骨图铺开可能的原因，用 5Why 追到根因，用归纳与演绎确认结论的可靠程度，最后用金字塔原理把结论讲出来。

## 使用建议

这些框架单独用效果有限，组合起来才有力。最常见的三种组合是：

- **鱼骨图 + 5Why**：先横向铺开所有可能的原因，再对最可疑的那条纵向追问到底，用于故障排查和质量改进。
- **逻辑树 + MECE**：用 MECE 作为每一层的验收标准，把问题逐层拆到可以分配、可以验证的粒度。
- **假设驱动 + 金字塔原理**：用假设驱动快速收敛验证范围，用金字塔原理把验证结果组织成结论先行的汇报。

还有两种适合日常场景的轻量组合：

- **5W2H + 金字塔原理**：下达任务或写需求时用 5W2H 补全要素，向上汇报时用金字塔原理组织结论。
- **MECE + 归纳与演绎**：分类完成后向上概括结论时，用归纳方式表达，让读者可以逐条检验。

### 使用框架的三条原则

第一，**先想清楚要回答什么问题，再挑框架**。框架是用来服务问题的，不是反过来。拿着一把锤子看什么都像钉子，是使用这类工具时最常见的失败。

第二，**框架的价值在于稳定，而不是深刻**。它们不会替你产生洞见，但能稳定地防止你在状态不好或时间紧张时漏掉关键环节。判断一个框架是否值得坚持用，标准是它能否在你最忙的时候仍然被执行。

第三，**做完之后一定要回头验证**。无论是分类、拆解还是追因，只要结论没有用数据或事实核对过，它就还只是一个假设。这一步是这套方法里最容易被省略、也最不能省略的一步。

需要提醒的是，框架只是检查表，它不会替你产生洞见。真正的价值在于它能稳定地防止你漏掉某些环节，而不是让你在状态好的时候表现更好。把它们做进日常的模板和流程里，比偶尔想起来用一次更有意义。
