# 归纳与演绎

[[toc]]

归纳是从个别事实出发概括出一般结论，演绎是从一般原理出发推导出个别结论，两者是人类最基本的两种推理方式。它们解决的问题是：如何从已知推出未知，以及如何判断一个结论究竟有多可靠。写论证、做研究、搭指标体系、设计产品规则的人，都需要清楚地知道自己此刻是在归纳还是在演绎，因为两者的可靠程度和适用条件完全不同。

## 一句话概括

> 归纳是从个别到一般，结论是或然的；演绎是从一般到个别，前提为真且形式有效时结论必然为真。

## 核心思想

**归纳的典型形式是：观察到若干个案都具有某个特征，于是推断该类事物普遍具有这个特征。** 例如连续三个月的数据都显示复购率下降，于是判断“复购率在持续下滑”。归纳的结论超出了已知事实的范围，因此它天然带有不确定性——只要出现一个反例，结论就要被修正。这也是为什么归纳结论必须用“通常”“大概率”这类限定词，而不能说成绝对真理。

**演绎的典型形式是：从一个普遍命题出发，通过有效的推理形式推出一个具体结论。** 最经典的演绎形式是三段论，由亚里士多德系统阐述：所有人都会死，苏格拉底是人，所以苏格拉底会死。演绎的特点是，只要前提为真、推理形式有效，结论必然为真。它不产生新知识，但它能把隐含在前提里的信息显式地推出来，这是它在工程和数学中极其重要的原因。

两种推理的可靠性来源不同，因此使用方式也不同。归纳的风险在于**样本的代表性**：样本太少、样本有偏、只看到了支持结论的案例而忽略了反例，都会让归纳出错。演绎的风险在于**前提的真实性**：推理过程再严密，如果前提是错的，结论照样是错的。所以归纳要反复问“我看到的样本够不够全”，演绎要反复问“我的前提成立吗”。

在结构化思考中，这两种推理承担不同角色。**向下拆解问题主要用演绎**：从一个判断推出它成立所需的条件，例如“要提升利润，就要么提高收入要么降低成本”。**向上概括结论主要用归纳**：从一组具体事实概括出一句判断，例如“三个渠道的获客成本都在上升，因此整体获客效率在下降”。金字塔原理的“以上统下”正是要求这两个方向交替成立。

芭芭拉·明托在《金字塔原理》中特别建议：**表达时优先使用归纳，而不是演绎**。原因是演绎是线性的，读者必须跟着你一步一步走完整个链条才可能接受结论，链条上任何一步被质疑，整段论证都要重来；而归纳是并列的，读者可以逐条独立检验，即使某一条不成立，其余几条仍然支撑结论。所以同样的内容，用归纳方式呈现，读者接受起来阻力更小。

最后需要知道归纳有一个哲学上的著名难题。休谟指出，归纳推理的合理性本身无法被证明：我们用“过去一直如此”来论证“未来也会如此”，而这个论证本身又依赖归纳，构成循环。这不意味着归纳不可用，而是提醒我们，归纳结论永远只是当前证据下的最佳猜测，需要随着新证据不断修正。

### 两种推理的对比

| 对比项 | 归纳 | 演绎 |
| --- | --- | --- |
| 方向 | 从个别到一般 | 从一般到个别 |
| 典型形式 | 观察到多个同类案例，概括出规律 | 三段论：大前提、小前提、结论 |
| 结论的可靠性 | 或然，可能被反例推翻 | 必然，前提为真且形式有效时成立 |
| 主要风险 | 样本不足或有偏 | 前提不真实 |
| 检查重点 | 样本是否具有代表性 | 前提是否成立、推理形式是否有效 |
| 是否产生新知识 | 会产生超出已知事实的新判断 | 不产生新知识，只把前提里隐含的信息显式化 |
| 表达上的特点 | 并列结构，读者可逐条检验 | 线性结构，读者须跟完整条链 |

需要注意的是，两种推理在实际分析中几乎总是交替出现，很少有纯粹只用一种的论证。区别只在于你此刻正处在哪一段，以及该段的可靠性由什么决定。

### 三段论与常见的形式错误

三段论的两种典型谬误值得单独记住，因为它们在日常讨论中出现频率极高。

| 形式 | 写法 | 问题 |
| --- | --- | --- |
| 肯定后件 | 若 A 则 B；观察到 B；故 A 成立 | B 可能有别的原因，A 只是其中一种 |
| 否定前件 | 若 A 则 B；A 不成立；故 B 不成立 | B 可能由其他条件导致，与 A 无关 |

用产品分析的话说，就是“付费用户都看过引导页，所以看过引导页就会付费”和“没做活动就没有增长，所以做活动就有增长”，两者都经不起推敲。

## 怎么用

1. **先分清当前任务的方向**。你是在从事实找规律（归纳），还是在从原则推具体结论（演绎）。方向不同，检查重点不同。
2. **做归纳时先收集样本**。列出所有能找到的相关案例或数据，而不是只列支持自己想法的那些。
3. **检查样本的代表性**。样本量够不够、来源是否有偏、是否覆盖了不同时间与不同场景、有没有被忽略的反例。
4. **给出带限定的结论**。把结论写成“在什么范围内、大概率成立”的形式，明确它适用的边界。
5. **做演绎时先写出前提**。把用到的普遍命题明确写出来，不要让它藏在论证的缝隙里。
6. **检查前提是否真实**。逐条确认前提有没有事实支撑，前提错了，后面全错。
7. **检查推理形式是否有效**。常见错误是肯定后件、否定前件，形式不对，前提真也推不出结论。
8. **两者结合使用**。用演绎确定要验证哪些条件，用归纳从验证结果中提炼结论，再用演绎把结论落到具体行动。

## 示例

用同一个场景展示两种推理的差别：某团队要判断“新版本是否导致了用户流失”。

演绎路径：

| 步骤 | 内容 |
| --- | --- |
| 大前提 | 如果新版本存在导致用户无法完成核心操作的问题，那么受影响用户会流失 |
| 小前提 | 数据显示新版本上线后，部分用户的核心操作成功率从 98% 下降到 71% |
| 结论 | 这批用户中的流失大概率与新版本有关，应当优先修复该问题 |

演绎的价值在于它把需要验证的关键条件清楚地写了出来——核心操作成功率是否下降。团队可以立刻去核对这个数字，而不是泛泛地讨论版本好坏。

归纳路径：

| 观察到的个案 | 事实 |
| --- | --- |
| 案例一 | 用户 A 在升级后连续三天未登录，回访表示“找不到原来的入口” |
| 案例二 | 用户 B 的订单在升级后提交失败两次，之后未再下单 |
| 案例三 | 用户 C 未反馈任何问题，但使用频次从每天 4 次降到每周 1 次 |
| 案例四 | 用户 D 升级后正常使用，未受影响 |

从这四个个案归纳，只能得出“部分用户的流失与新版本体验有关，但并非所有用户都受影响”这样的有限结论。样本只有四个，且都是主动联系得到的，存在明显选择性偏差，不能直接推广到全部流失用户。要得到更可靠的结论，需要扩大样本或结合行为数据分析。

把两条路径合起来用，才是完整的分析：先用演绎确定“核心操作成功率下降会导致流失”这个可验证的条件，再用大量行为数据归纳出成功率下降与流失之间的实际关系，最后用演绎把结论落到具体的修复动作上。

## 适用场景

- 写作与表达：判断一段论证是在归纳还是在演绎，据此决定用什么结构呈现。
- 商业分析：从数据中发现规律（归纳），或从业务规则推出指标之间的关系（演绎）。
- 指标设计：用演绎搭建指标之间的公式关系，用归纳验证关系是否符合实际数据。
- 产品规则设计：从一般原则推导具体规则，再从用户行为数据归纳规则是否合理。
- 研究方法：设计实验、抽样、验证结论时的基本逻辑框架。
- 面试与辩论：识别对方论证中的推理类型，找到可以攻击的薄弱环节。
- 决策判断：判断手上的证据究竟支持到什么程度的结论。

## 常见误区

- **把归纳结论说成必然**。用有限样本得出“所有情况都如此”的判断，忽略了反例的可能性。
- **样本有偏**。只访谈了愿意回复的用户，就把结论推广到全体用户。
- **只找支持证据**。带着结论去找证据，忽略掉与之矛盾的数据。
- **演绎前提不实**。“用户都喜欢便宜的东西”这类未经验证的前提，会让推理链整体失效。
- **推理形式错误**。由“如果 A 则 B”和“B 成立”推出 A 成立，这是典型的肯定后件谬误。
- **把相关当因果**。两件事同时变化只是相关，要成为因果还需要额外证据。
- **混用两种推理却不自知**。一段论证里前半段归纳、后半段演绎，却没有说明衔接依据。
- **在表达中滥用演绎**。把简单结论写成多段推理，读者还没走完就已经不信了。

## 相关工具

- **金字塔原理**：明托把归纳与演绎作为同一组思想的两种组织方式，并建议表达时优先使用归纳。
- **MECE 原则**：归纳概括的前提是分组不重不漏，否则概括出的结论会带有系统性偏差。
- **逻辑树**：向下拆解主要用演绎，向上汇总主要用归纳，同一棵树上两种推理交替出现。
- **假设驱动与议题树**：从假设推出需要验证的条件属于演绎，从验证结果概括判断属于归纳。
- **5Why 分析法**：因果链条的每一环都是一次演绎，而判断是否到达根本原因则依赖归纳经验。
- **鱼骨图**：把归纳出来的多条原因按类别组织，便于逐条验证因果方向是否成立。
