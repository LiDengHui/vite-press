# ORID焦点讨论法

[[toc]]

ORID 焦点讨论法是一种引导团队讨论的提问框架，把对话分成四个层次：客观（Objective）、反映（Reflective）、诠释（Interpretive）、决定（Decisional）。它解决的是"怎么让一群人从事实出发、经过感受和思考、最终形成结论和行动"的问题。主持会议、工作坊引导、复盘讨论、团队共识时，常用它来设计问题、控制节奏。

ORID 来自引导技术领域，关注的是如何让讨论有序展开，而不是让声音最大的人主导全场。它把"从看到什么、感觉到什么，到想到什么、决定做什么"这个自然的思考过程，固定成四个可操作的提问层次。

## 一句话概括

> 先问大家看到了什么，再问有什么感受，然后问这意味着什么，最后问打算怎么做。

四层由表及里、由感性到理性，让讨论既有温度又有结论。

## 核心思想

ORID 的第一层是"客观"，关注事实和感官信息。问的是"你看到了什么""你听到了什么""有哪些数据"。这一层的目的是让大家先对齐事实，避免一上来就各说各话、各持立场。缺少事实基础的讨论，很容易变成观点的碰撞。

第二层是"反映"，关注情绪和直觉反应。问的是"这让你有什么感受""哪一点让你印象最深""你联想到什么"。情绪是真实存在的，忽略它会让讨论变得生硬。让情绪先被表达出来，参与者才更容易进入理性思考。

第三层是"诠释"，关注意义和思考。问的是"这意味着什么""我们从中能学到什么""这和我们之前想的有何不同"。这一层是讨论的核心，把事实和感受转化为理解和判断。

第四层是"决定"，关注行动和决策。问的是"我们接下来做什么""谁负责、什么时候完成""我们达成了什么共识"。没有这一层，讨论再热烈也落不到实处，会议开完依然没有改变。

四层的顺序很重要，它是从具体到抽象、从感性到理性的自然过程。如果跳过前两层直接谈决定，参与者往往还停留在情绪或各自的立场上，决定难以形成共识。如果停在诠释层不做决定，讨论就成了空谈。

ORID 的每一层都通过提问来引导，而不是由主持人给出答案。主持人的角色是设计问题、控制节奏、保证每个人都有发言机会，而不是替大家下结论。这种"提问而不说教"的方式，能显著提高参与感。

问题设计是 ORID 的难点。好的问题应该开放、具体、与主题直接相关，并且能自然地引向下一层。比如从"你注意到了哪些数字"过渡到"哪个数字最让你意外"，就把客观和反映连了起来。

ORID 也常用于个人反思。一个人复盘一段经历时，同样可以依次问自己：发生了什么、我当时什么感受、这意味着什么、下一步我该怎么做。它让反思更有结构，不容易停留在情绪里。

需要提醒的是，ORID 是一套引导方法，需要主持人有耐心和掌控力。在时间紧张或议题简单的场合，可以压缩层次，但顺序最好保持，否则容易失去它引导讨论的价值。

ORID 的四个层次也可以根据议题调整。有些议题事实复杂，客观层需要更多时间；有些议题情绪浓重，反映层要留足空间。灵活分配时间，比机械地平均用力更重要。

主持 ORID 讨论时，沉默也是有用的。抛出问题后不要急着填补空白，给参与者思考的时间。很多有价值的发言，恰恰出现在几秒钟的安静之后。

ORID 也适合用于一对一的沟通。比如辅导下属时，先问事实、再问感受、然后讨论意义、最后定行动，能避免一上来就给建议，让对方更有参与感。

最后，ORID 的效果取决于问题的质量。问题太笼统，讨论就会浮于表面；问题太封闭，又限制了思考。多准备一些开放而具体的候选问题，现场才能灵活应对。

## 怎么用

1. 明确讨论主题与目标。先说清这次讨论要解决什么问题、期望产出什么。
2. 设计客观层问题。围绕事实和数据提问，让大家对齐"发生了什么"。
3. 设计反映层问题。引导表达感受和直觉，让情绪先被看见。
4. 设计诠释层问题。推动思考和解读，形成对意义的共识。
5. 设计决定层问题。落到具体行动，明确谁做什么、什么时候完成。
6. 控制节奏与参与。保证每层都有足够时间，让每个人都有机会发言。

准备时，可以先把四个层次各写两三个候选问题，再根据现场情况灵活选择，而不是照本宣科地念问题。

## 示例

以一次项目复盘会为例，按 ORID 四层设计问题。

| 层次 | 引导问题 |
| --- | --- |
| 客观 O | 这次项目原计划什么时候上线？实际什么时候上线？期间出现了哪些问题？ |
| 反映 R | 哪个环节让你最焦虑？问题解决的那一刻你是什么感受？ |
| 诠释 I | 这次延期暴露了哪些流程上的短板？我们在需求评审环节需要改变什么？ |
| 决定 D | 下次项目我们要保留哪三条做法、改掉哪两条做法？谁来跟进流程调整？ |

现场通常不是机械地一问一答，而是层层推进：

| 阶段 | 现场表现 |
| --- | --- |
| 客观 | 大家列出时间线和问题清单，逐步对齐事实 |
| 反映 | 参与者开始说出当时的压力和担心，气氛变得坦诚 |
| 诠释 | 讨论聚焦到流程短板，形成两三条共同判断 |
| 决定 | 明确两项流程改动和负责人，会议以行动收尾 |

同样的问题设计也可以用于个人复盘：把四层问题写下来，逐层回答，最后落到一个具体的下一步行动。

## 适用场景

- 会议主持与议程设计
- 团队复盘与经验总结
- 工作坊与培训引导
- 战略讨论与共识达成
- 社区与群体对话
- 个人反思与自我复盘
- 冲突后的沟通与修复
- 需求评审与头脑风暴的收束
- 用户访谈的问题设计
- 焦点小组讨论的引导
- 读书会与学习小组的组织
- 年度规划会的议程设计
- 一对一的辅导对话
- 敏捷回顾会议的主持

## 常见误区

- 跳过事实直接讨论。不先对齐客观信息，讨论变成观点碰撞。
- 忽略情绪层。不给情绪表达的空间，参与者难以进入理性思考。
- 停在感受不往前。讨论充满情绪却推不到诠释和决定。
- 只有决定没有铺垫。直接问"怎么做"，共识难以形成。
- 主持人替大家下结论。用引导变成说教，参与感下降。
- 问题太封闭。只问"是或否"，无法引出深入讨论。
- 时间分配失衡。某一层拖太久，其他层草草收场。
- 决定层落空。讨论热烈却没人负责、没有期限。

## 相关工具

- SBI 反馈模型：给出具体反馈的结构，可用于讨论中的事实层。
- 非暴力沟通：处理情绪化对话的框架，与 ORID 的反映层呼应。
- SCQA 结构：需要铺垫背景时的开场结构。
- PREP 表达法：结论先行的表达模板，适合收敛结论。
- STAR 法则：叙述经历的结构，可用于复盘时的经历陈述。
- 决策矩阵：当讨论进入决定层且涉及方案选择时，用矩阵补充依据。
- 金字塔原理：帮助把讨论结论组织成有逻辑的汇报。
