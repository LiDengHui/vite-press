# CSS 层叠与堆叠上下文

CSS 中的「层叠」有两个维度：
- **Cascading（层叠）**：解决样式冲突的规则（优先级、来源、顺序）
- **Stacking（堆叠）**：元素在 Z 轴上的叠加顺序（z-index、层叠上下文）

---

## 一、层叠三大规则（Cascading）

当多个样式作用于同一元素时，按以下顺序判定：

```text
来源与重要性 → 层叠层（@layer）→ 特异性 → 作用域距离 → 源码顺序
```

同一来源、同一层内，优先级从高到低为：

```
!important > 行内样式 > ID > 类/伪类/属性 > 元素/伪元素 > * > 继承
```

| 来源 | 权重 |
|------|------|
| 用户代理样式（浏览器默认） | 最低 |
| 用户自定义样式 | 中 |
| 作者样式（页面 CSS） | 高 |
| `!important` | 最高 |

> 同优先级时，**后写的覆盖先写的**（源码顺序）。

### 层叠层（@layer）

`@layer` 在特异性之前先把声明分桶。层顺序在第一次出现时确定，后声明的层优先级更高；同一层内部才比较特异性。

```css
@layer base, components, utilities;

@layer base {
    #app .btn { color: blue; } /* 特异性高，但在更早的层 */
}

@layer utilities {
    .btn { color: red; } /* 最终生效 */
}
```

| 声明类型 | 从低到高 |
| --- | --- |
| 普通声明 | 最早层 → 最晚层 → 未分层 → 行内 `style` |
| `!important` | 未分层 → 最晚层 → 最早层 → 行内 `!important` |

> 动画（`@keyframes`）高于普通声明，过渡（`transition`）高于 `!important`。完整用法见 [CSS 级联层 Cascade Layers](./CSS%20级联层%20Cascade%20Layers.md)。

## 二、层叠上下文（Stacking Context）

层叠上下文是 HTML 元素在三维空间（X/Y/Z）中的一个独立渲染层。元素在 Z 轴上的顺序由层叠上下文决定。

### 触发层叠上下文的常见条件

1. `position` 为非 `static` 且 `z-index` 不为 `auto`
2. `position: fixed` 或 `position: sticky`（无需 z-index）
3. `opacity < 1`
4. `transform` 不为 `none`
5. `filter` 不为 `none`
6. `will-change` 设为 `transform`、`opacity` 等
7. `display: flex/grid` 且子元素 `z-index` 不为 `auto`
8. `isolation: isolate`
9. `mix-blend-mode` 不为 `normal`

### 层叠顺序（由低到高）

```
1. 层叠上下文背景/边框
2. 负 z-index 子元素
3. 普通流块级元素
4. 浮动元素
5. 行内/行内块元素
6. z-index: 0 / auto 的定位元素
7. 正 z-index 子元素（值越大越在上）
```

> ⚠️ **关键规则**：子元素的 z-index 只在父层叠上下文内比较。如果父元素的层叠级别低，子元素 z-index 再高也无法突破父级限制。

---

## 三、z-index 使用误区

### ❌ 误区 1：z-index 越大就一定在上

```css
/* A 的父级没有层叠上下文，B 的父级创建了 */
.parent-a { }                 /* 普通流 */
.parent-b { opacity: 0.9; }  /* 创建了层叠上下文 */

.child-a { z-index: 9999; }   /* 再高也没用 */
.child-b { z-index: 1; }
```

**结果**：`child-b` 会覆盖 `child-a`，因为 `parent-b` 的层叠上下文整体在 `parent-a` 之上。

### ❌ 误区 2：随意使用超大数值

```css
/* 这种写法毫无意义 */
.modal { z-index: 999999; }
.toast { z-index: 9999999; }
```

**正确做法**：按层级体系分级管理：

```css
:root {
    --z-base: 0;
    --z-dropdown: 100;
    --z-sticky: 200;
    --z-fixed: 300;
    --z-modal-backdrop: 400;
    --z-modal: 500;
    --z-popover: 600;
    --z-tooltip: 700;
    --z-toast: 800;
}
```

## 四、调试技巧

在 Chrome DevTools → Layers 面板可以直观看到：
- 当前页面有哪些层叠上下文
- 每个元素的层叠顺序
- 哪些属性触发了层叠上下文

快捷键：`Cmd + Shift + P` → 输入 "Layers"

## 五、奇淫技巧

### 技巧 1：用 `isolation: isolate` 创建干净层叠上下文

```css
/* 不改动布局，无副作用地创建层叠上下文 */
.component {
    isolation: isolate;
}
.component-popup {
    z-index: 10; /* 只在 component 内部比较 */
}
```

### 技巧 2：用 `opacity: 0.999` 强制提升层级（不推荐生产环境）

```css
/* 无 z-index 也能创建层叠上下文，hack 级用法 */
.hack-layer {
    opacity: 0.999;
}
```

### 技巧 3：解决弹窗被覆盖的终极方案

```css
/* 将弹窗挂载到 body 层级，避免父级层叠上下文限制 */
body > .global-modal {
    position: fixed;
    z-index: var(--z-modal);
    isolation: isolate;
}
```

> 💡 总结：理解层叠上下文的关键是——**z-index 只在同层叠上下文中比较**，父级上下文决定了整体的上下关系。
